# コードの複雑度を最小化する

外部契約を満たす候補の中から、理解と変更に必要な概念、状態、経路、依存、コード、テストが最も少ない実装を選ぶ。
単一の合成スコアは作らず、局所値、全体値、対抗指標を並べて改善する。
実測された性能要件がない限り、実行速度や理論上の計算量より単純さを優先する。

## 品質ゲート

次の条件を満たさない案は、複雑度の値が小さくても採用しない。

- 外部契約、事前条件、事後条件、不変条件、失敗条件を満たす。
- 測定対象、除外対象、ツール、バージョン、設定を変更前後で固定する。
- 契約項目をテスト義務へすべて対応づけ、義務充足率を100%にする。
- format、静的解析、関連する単体、結合、E2Eテストを通す。

テスト、カバレッジ、現実装を契約の全体と見なさない。
契約を狭める、失敗条件を消す、測定対象を除く、入力をハードコードする方法で数値を改善しない。

## 契約違反を即座に失敗させる

信頼境界では、外部契約が要求する入力検証を一度だけ行う。
境界を通過した値は契約を満たすものとして扱い、後段で再検証しない。
内部の事前条件と不変条件は、`assert`、`panic`、`precondition`、`check` などで簡潔に表し、正しさに必要なら本番でも有効な機構で違反時に停止する。

不正な値を空値、ゼロ、既定値、既知の列挙値へ黙って補正しない。
解析失敗や例外を無視せず、推測による再解釈、成功に見えるfallback、起こらない状態への復旧や再試行を加えない。
障害回復、互換性、可用性、セキュリティ上の拒否が契約なら、その処理だけを境界へ隔離する。

## KPIを組で測る

利用可能な指標を同じ範囲で測る。
各行の一項目だけを改善せず、局所値、全体値、対抗指標を比較する。

| 対象 | 局所値 | 全体値 | 対抗指標 |
| --- | --- | --- | --- |
| 制御フロー | 認知的複雑度と循環的複雑度の最大値 | 両複雑度の合計値、閾値超過関数数 | 関数総数、最大呼び出し深度、追跡する関数、構成要素、ファイル数 |
| コード量 | 関数、構成要素ごとの整形後行数 | 手書き本体の総行数、論理文数 | 関数、型、公開シンボル、重複ブロック、動作を決める設定の総数 |
| 状態 | 構成要素ごとの意味上の状態数 | 到達可能状態数、許可遷移数 | 独立した可変状態、重複事実、同期状態、不変条件の総数 |
| データ | 一概念に使う表現数 | 変換数、保存する事実数 | nullable、真偽値フラグ、動的キー、型で表せない制約の総数 |
| 依存 | 最大fan-out | 依存辺、循環依存、強連結成分の総数 | グローバル、イベント名、設定キー、外部サービスなどの暗黙依存数 |
| 責務 | 構成要素ごとの変更理由、不変条件群 | 最大構成要素サイズ、公開契約総数 | 委譲だけの分割、内部表現を共有する構成要素数 |
| 公開API | APIごとの引数、動作モード数 | 公開シンボル、引数、動作ケースの総数 | 真偽値オプション、文字列モード、汎用マップ、動的ディスパッチ数 |
| テスト | 一ケースの義務と失敗理由 | 義務充足率、論理ケース、冗長ケースの総数 | 詰め込み、層間重複、生存ミュータント、テストコード量と複雑度 |

認知的複雑度と循環的複雑度は最優先の数値指標とし、最大値と合計値を必ず併記する。
リファクタリングでは一項目以上を改善し、対になる指標を理由なく悪化させない。
機能追加とバグ修正では、契約を満たす候補間で増加量を比較する。

## 測定規則

- 生成物と外部ライブラリは除外し、手書きの本体、生成元、設定、SQL、テンプレート、スキーマを含める。
- テストと文書は本体コード量から除外するが、品質ゲートと専用KPIから除外しない。
- formatter適用後に測り、複数文の一行化、短い名前、巨大な式や正規表現を削減と数えない。
- 意味上の状態は外部挙動または許可操作が異なる状態とし、符号化を変えても同じ状態と遷移なら削減と数えない。
- 分岐を表、設定、ハンドラー、継承、例外、再帰、非同期処理、メタプログラミングへ移しても経路として数える。
- 外部依存には、その契約、設定、変換、通信、失敗条件を含める。
- 測定不能な値は推測せず、固定した規則で手作業計測するか理由を添えて未測定とする。

ゼロ目標は、重複して保存する事実、循環依存、未記録の暗黙依存、未検証のテスト義務、冗長テストを0にすることである。
最小化目標は、KPI表の残りの値を品質ゲートとゼロ目標を保ったまま減らすことである。

## テストを必要最小限にする

**テスト義務**は、外部契約に照らして独立に破れ得る振る舞いの単位とする。
契約条項、同値クラス、振る舞いが変わる境界と組合せ、状態遷移、失敗条件、統合境界、過去の不具合で判明した契約から義務を列挙する。
同じケースで検証できても、独立して破れる契約上の主張は別義務として数える。
違反実装で対応テストが失敗するときだけ、その義務を検証済みと数える。

次の値を記録する。

| 記号 | 定義 | 目標 |
| --- | --- | --- |
| `U` | 義務へ未対応の契約項目数 | `0` |
| `O`, `O_v` | 義務総数、検証済み義務数 | `O_v / O = 100%` |
| `T`, `T_r` | 論理ケース総数、削除しても検出能力が変わらないケース数 | `T_r = 0`の後に`T`を最小化 |
| `P`, `D`, `F` | 独立シナリオの詰め込み、理由のない層間重複、不安定または再試行依存のケース数 | `0` |
| `M` | 契約に関係する非同値の生存ミュータント数 | 利用可能なら`0` |
| `L_t`, `C_t` | 整形後テスト行数、テスト複雑度の最大値と合計値 | 両方の最大値と合計値を最小化 |
| `H`, `I`, `R` | fixture、helper、matcher、double数、最大間接深度、実行時間 | 最小化 |
| `T_u`, `T_i`, `T_e` | 単体、結合、E2Eの論理ケース数 | 最も狭い層で最小化 |

一つの論理ケースは、一つのまとまったシナリオと失敗理由を持つ。
テスト関数、アサーション、パラメーター行の見かけではなく、独立した入力と期待結果を数える。
巨大なデータ表、スナップショット、fixture、helper、性質の結合へ複数のケースや義務を隠さない。
性質ベーステストは生成入力数ではなく、契約上の性質、同値クラス、境界を数える。
`L_t`には、手書きのテスト入力、fixture、snapshotを含め、テスト関数または補助要素ごとの最大値と全体の合計値を併記する。

各義務は、異なる故障を検出する理由がない限り、最も狭い一層だけで検証する。
テストダブルは制御不能な外部境界に限り、内部手順ではなく公開契約の結果を検証する。
各ケースを一つずつ削除して義務、必要な分岐と遷移、ミュータントの検出集合が変わらないなら削除する。
さらに、複数ケースを一つの性質または同値クラスの代表へ置換できないか確認する。

ミューテーションの対象、演算子、除外規則は変更前に固定する。
同値または契約外の個体だけを理由付きで除外し、ミュータントだけを根拠に新しい義務を作らない。
カバレッジは観測値として使い、実装の分岐やカバレッジから義務を逆算しない。

## 単純な設計を選ぶ

- 一つの概念を一つの値または構造で表し、導出できる事実を保存しない。
- 不正状態を表現しやすい真偽値、nullable、汎用マップより、列、レコード、直和型を選ぶ。
- 変換は外部境界または意味が変わる箇所だけに置き、処理中の正準な識別子を一つにする。
- 同じ不変条件と変更理由を持つ状態と操作を、一つの所有者へまとめる。
- 依存を入口から中核へ向け、共有可変状態、遠隔更新、循環依存を避ける。
- 抽象化は公開知識と変更影響を減らす場合だけ導入し、単一実装のinterface、委譲だけの層、将来用拡張点を作らない。
- 対象外要素を入口で除き、主処理をガード節、選択、変換、集約として表す。
- 宣言的な標準APIが意図を短くする場合は使い、可変変数のスコープと寿命を最小化する。
- 関数の短さ自体を目標にせず、意味または契約を分離しない小関数を作らない。
- キャッシュ、索引、並列化、特殊な構造は、代表入力の測定値と要求値が必要性を示す範囲だけに置く。

## 改善ループ

1. 外部契約、失敗条件、許可された変更、既存テストを確認する。
2. 測定範囲と条件を固定し、変更前のKPIを記録する。
3. 状態、遷移、変換、責務、依存とテスト義務を列挙する。
4. 未検証の義務に対する最小のテストを追加し、失敗を確認する。
5. バグ修正では不具合の再現テストを最初に失敗させる。
6. 最も単純なデータ表現から実装し、追加したテストを通す。
7. 義務充足率が100%になるまで手順4から6を繰り返す。
8. 重複した事実、状態、経路、変換、型、依存、テストを削除し、より単純な表現へ置換する。
9. 同じ条件で再測定し、局所値、全体値、対抗指標を比較する。
10. 単独削除だけでなく複数要素の統合、置換、責務再配置も比較し、複雑さの移動がなく改善案がなくなるまで手順8と9を繰り返す。
11. 検証を実行し、契約、設計文書、利用方法を実装と一致させる。

交換条件が残る場合は、正しさ、データと状態、依存、認知的複雑度、循環的複雑度、コード量、実測性能の順で判断する。

## 完了報告

変更前後のKPIを、同じ測定範囲、条件、ツール、設定とともに表で報告する。
少なくとも、本体とテストの認知的複雑度と循環的複雑度の最大値と合計値、本体とテストのコード量、関数総数、`U`、`O`、`O_v`、`T`、`T_r`を含める。
測定できる場合は、状態、遷移、変換、依存辺、公開契約、`P`、`D`、`M`、`F`、`H`、`I`、`R`、`T_u`、`T_i`、`T_e`も含める。
未測定値には理由を書き、悪化した値には必要な契約と採用しなかった単純な代替案を書く。
